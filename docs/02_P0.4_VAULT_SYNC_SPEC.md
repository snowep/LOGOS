# LOGOS — P0.4 Vault Synchronization Specification

## Branch

`p0.4-vault-sync`

Create this branch only after `p0.3.1-foundation-alignment` passes.

## Definition

P0.4 means:

> LOGOS can reliably observe, index, reconcile, and modify its Markdown workspace without silent data loss.

## Canonical watcher flow

```text
Filesystem
 -> Watcher
 -> Normalize event
 -> Identify document
 -> Read/hash
 -> Compare known state
 -> Update document
 -> Record event
 -> Publish lightweight event
 -> Evaluate memory promotion
```

## LOGOS write flow

```text
Intent
 -> Read current document
 -> Check expected version/hash
 -> Authorize
 -> Atomic write
 -> Register actor
 -> Watcher observes
 -> Recognize actor
 -> Update state
 -> Verify final hash
```

## Supported files

Only:

```text
.md
.markdown
```

Default max size:

```text
10 MB
```

Ignore dotfiles, node_modules, temp files, backups, logs, databases, and binaries.

## Event schema

Every event contains:

```text
event_id
document_id
event_type
path
previous_path
version
hash
writer_identity
timestamp
metadata
```

Events:

```text
created
modified
deleted
renamed
moved
```

## Writer identity

```text
USER
LOGOS
AGENT
AUTOMATION
```

Direct external filesystem edits may default to USER.

Internal writes must explicitly carry the actor.

## Rename strategy

Because filesystem watchers often emit unlink/add instead of semantic rename:

1. store a pending deletion record,
2. wait a bounded interval,
3. compare incoming add by hash,
4. match old document ID when evidence supports it,
5. otherwise keep delete + create.

Never claim rename certainty without evidence.

## Reconciliation

`POST /api/vault/reconcile` must be real and idempotent.

Example:

```json
{
  "status": "reconciled",
  "created": 2,
  "modified": 3,
  "deleted": 1,
  "renamed": 1,
  "conflicts": 0,
  "skipped": 2
}
```

Second run with no changes must report zero changes.

## Conflict

A conflict exists when an operation is based on an old state.

Example:

```text
LOGOS reads v7 hash ABC
USER changes file
file becomes v8 hash XYZ
LOGOS writes expecting v7/ABC
```

Return:

```text
409 CONFLICT
```

Do not silently overwrite.

## Sync UI

Only display "Synced" after actual reconciliation completes.

States:

```text
Ready
Syncing...
Synced just now
Sync failed
Conflict needs attention
```

## SSE

Send metadata, never complete file contents.

Good:

```json
{
  "documentId": "...",
  "event": "modified",
  "path": "projects/drop-002.md",
  "version": 8,
  "hash": "...",
  "writer": "USER"
}
```

Browser behavior:

```text
SSE event
 -> invalidate relevant query
 -> refetch
 -> render
```

Do not duplicate the whole database in React.

1. create Markdown
2. modify Markdown
3. delete Markdown
4. rename Markdown
5. move Markdown
6. rapid repeated edits
7. edit non-Markdown
8. >10 MB file
9. LOGOS write
10. AGENT write
11. AUTOMATION write
12. conflict
13. clean reconciliation
14. changed reconciliation
15. SSE reconnect
